# 2026-10-24 实机调试补充

设备环境：MiTV-MFTP0，Android 9 / API 28，固件 6129。本文只记录本轮实际结果；不包含家庭地址、设备标识、账号或原始日志。

## 爆米花与播放器共存

- 从网易官网下载并安装网易爆米花 TV 2.6.23（`com.netease.filmlytv`，versionCode 1392），包含 armeabi-v7a，minSdk 21。安装包 SHA256：`fee4863c386bac0127781731fef4e1fbb7cac195807687e531932f6ba9640e86`。
- 用户完成首次确认与连接后，媒体库和观看记录可见。退出 MyTV、BBLL、Jellyfin 客户端，单独播放爆米花；用户明确确认画面和声音正常。无需迁移服务器上的片库。
- 曾观察到 MyTV 独立播放器与爆米花交替申请硬件解码器。退出其他播放器是有效的隔离步骤，但不能据此认定三个应用不能共存，也不能把所有播放问题归因于冲突。
- 此电视的视频播放截图多次为纯黑，而实际电视画面可正常显示。不能仅凭截图判断黑屏；需要结合用户观察、播放时间及解码状态。

## 电视直播约五秒循环：已修复并获用户确认

- 应用：电视直播 / MyTV 2.2.0.219，原全局播放内核 MEDIA3。用户反馈央视一台出现约五秒循环，换台后也一样。
- 对当前 HLS 清单间隔约 12 秒取样，序列从 8966574 前进至 8966575，切片列表也改变，且没有结束标记。可排除清单固定不更新这一种原因；不等于完整审计上游媒体内容。
- 先保存原配置，仅将 `videoPlayerSkipMultipleFramesOnSameVSync` 从 `true` 改为 `false`，随后重启直播应用。未同时改内核、软解、渲染模式、频道、账号或开机设置。
- 用户观察后确认“已经连续播放，不再循环”。保留关闭该选项，支持此机渲染兼容问题的判断。未宣称所有机型都需要此设置。
- 上游关于“跳过渲染多帧”的兼容说明见 [myTV tv2.2.7 发布记录](https://github.com/yaoxieyoulei/mytv-android/releases/tag/tv2.2.7)。安装版本的具体行为以本轮单变量实测为准。
- MyTV 仍引用原本 115 频道的独立本地 M3U；TVBox 使用的是此前更新的 112 频道文件，两套不能混为一谈。本轮未为修循环同时替换直播源。

## Projectivy 无障碍恢复：配置完成，开机守护仍待最终核验

原问题仍可复现：授权列表被改为仅含小米语音。不能清空所有服务或停用小米语音来修复。

已安装第三方开源 [AQinTrue/AccessibilityManager 10.3](https://github.com/AQinTrue/AccessibilityManager/releases/tag/v10.3)，包名 `com.accessibilitymanager`。下载 APK 的 SHA256 与官方发布元数据一致：

```text
2bff6a8c1a960d6196a7521910ca6ada5fe3276ec1b8faa6461aa7373b0c09f1
```

已检查该版本清单与核心代码：无 INTERNET 权限；恢复逻辑把守护目标合并到已有服务列表；保活无障碍组件不获取窗口内容，事件回调为空。它属于第三方软件，本项目不重新分发其 APK 或改变上游许可。

用户明确授权后，完成一次性的 `WRITE_SECURE_SETTINGS` 授权和电池优化白名单设置。这是持久、范围较广的系统权限，复现前应明确了解并接受权限范围。只将 Projectivy 加入守护名单，保留小米语音；管理器会启用自己的空保活服务。开机自动启动守护的菜单选项已确认勾选。

验证结果：

1. 当前会话的前台 DaemonService 已运行。
2. 模拟仅移除 Projectivy，守护在约 0.5 秒内自动补回；小米语音保留，系统确认 Projectivy 服务重新绑定。
3. 执行了一次真实重启，启动标识改变且系统报告启动完成。重启后约 30 秒，Projectivy、小米语音和管理器保活组件均已绑定，系统设置权限仍保留。
4. 该次观察只看到管理器保活组件，尚未确认 DaemonService 已随开机启动；随后固件关闭 ADB，不能把“重启后服务列表正常”当成“守护开机恢复已完整验收”。用户当前不方便再开 ADB，最终核验暂缓。

**状态：模拟恢复通过；一次真实重启后的绑定正常；后台守护的开机自启与长期恢复仍待核验。** 没有配置电脑常驻修复任务，也没有设置每次开机后依靠 ADB 修复的流程。

下一次核验应先读取 DaemonService 的状态与开机广播记录，再在已运行的守护下模拟丢失并确认实际绑定，最后观察第二次冷启动。不要为了检查而先手动打开管理器主页，否则可能掩盖它没有自动启动的问题。

## 停用与回滚

如不再使用该守护，应先从管理器移除 Projectivy 的守护锁，或卸载管理器，再执行原有 `restore.sh`。否则仍在运行的守护可能把脚本移除的 Projectivy 重新加入。

在电视端卸载“无障碍管理器”会一并撤销它的权限和后台组件；它不会清除 Projectivy 的桌面布局。也可在明确目标并允许调试后执行：

```bash
adb -s <电视IP>:5555 uninstall com.accessibilitymanager
```

直播循环修复需要回滚时，在电视直播播放器设置中重新开启“跳过渲染多帧”即可；本次原配置只保存在本地私有备份中。
